# AI-ҰСТАЗ: контекст для совместной работы

## Назначение проекта

Двуязычный курс «ИИ на службе учителя» из 36 микроуроков по использованию Higgsfield Supercomputer для подготовки учебных материалов.

Қазақша: бұл жоба — мұғалімдерге Higgsfield Supercomputer көмегімен сабақ материалдарын дайындауды үйрететін 36 шағын сабақтан тұратын екітілді курс.

## Основной источник

- `course/course-map.yaml` — карта курса и стабильные ID L01–L36.
- `course/glossary.md` — единая терминология RU/KK.
- `course/lessons/Lxx/work-order.yaml` — контракт конкретного урока.
- `course/lessons/Lxx/lesson.md` — основной двуязычный текст.
- `course/lessons/Lxx/video-script.md` — сценарий микроурока.
- `course/lessons/Lxx/prompts.md` — библиотека промптов.
- `course/lessons/Lxx/assignment.md` — практическое задание и артефакт.
- `course/lessons/Lxx/quiz.yaml` — мини-тест.
- `course/lessons/Lxx/qa-report.md` — отчёт проверки урока.
- `course/final-assessment/` — итоговое тестирование.
- `docs/reports/AI-USTAZ-language-audit-RU-KK-L01-L36.md` — языковые замечания и точные замены.
- `docs/reports/AI-USTAZ-video-scripts-audit-RU-KK.md` — рекомендации по видеосценариям.
- `docs/reports/AI-USTAZ-prompt-library-audit-RU-KK.md` — рекомендации по библиотеке промптов.

## Обязательные правила

1. Сохранять стабильные ID L01–L36, а также ID промптов, заданий и вопросов.
2. Русская и казахская версии должны быть равны по смыслу, порядку блоков, количеству шагов и требуемому результату.
3. Казахский текст писать как самостоятельный естественный текст, а не как буквальный перевод с русского.
4. Использовать простые слова и короткие предложения, понятные начинающим учителям.
5. Не выдумывать элементы интерфейса Higgsfield. Сомнительное отмечать:
   - RU: `[НУЖНА ПРОВЕРКА]`;
   - KK: `[ТЕКСЕРУ ҚАЖЕТ]`.
6. Не добавлять персональные данные учащихся. Использовать только вымышленные, обезличенные или обобщённые примеры.
7. Перед изменением терминов сверяться с `course/glossary.md` и обновлять их единообразно во всём проекте.
8. Один микроурок должен содержать только необходимые действия, без повторов и лишней сложности.
9. Не считать автоматический структурный PASS полноценным языковым одобрением.
10. После изменений запускать `python validate_project.py`.

## Порядок работы для следующего автора или агента

1. Прочитать этот файл и `README.md`.
2. Прочитать карту курса и глоссарий.
3. Открыть `work-order.yaml` нужного урока.
4. Изменять связанные файлы урока согласованно.
5. Проверить RU и KK отдельно, затем проверить их смысловой паритет.
6. Запустить валидатор.
7. Зафиксировать в commit message, какие уроки и какие типы файлов изменены.

## Текущий редакционный статус

Структура 36 уроков собрана. Перед публикацией требуются:

- применение языковых правок RU/KK;
- упрощение и частичная переработка видеосценариев;
- переработка библиотеки промптов с количеством вариантов по реальной необходимости;
- финальная проверка казахским редактором-носителем;
- проверка актуальных элементов интерфейса Higgsfield Supercomputer.
